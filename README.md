# SCWU Web MVP

A local Ryuko mirror match on Sport Court, built with TypeScript, Svelte 5, Phaser 3, Vite, and Vitest. Includes free practice, a simple CPU opponent, forward/backward movement, dashes, double jumps, standing/crouching/aerial attacks and guard, three-step standing attack chains, Drill Punch, Hit Up launcher and jump chase, the three-part IORI chain, Axe throw, close-range throws, knockdowns and get-ups, hit/block reactions, KO/victory/draw animations, health, a 60-second CPU round, pause, reset, and touch controls.

## Run

Use Bun 1.3.9+, Node 24.12+ for the tooling CLIs, and Python 3.10+. Keep the supplied `scwu-web-handoff/` directory beside `package.json`.

```sh
bun install
bun run dev
```

Open the localhost address Vite prints. `predev` converts only the required art with the handoff's standard-library Python decoder. Missing or changed Ryuko source data produces an explicit error. No Python, Windows runtime, original executable, or backend is needed by the browser.

```sh
bun run validate # export assets, formatting, ESLint, types, Vitest
bun run build    # export assets, types, production build
bun run preview  # serve the production build locally
bun run format  # apply Prettier
```

`bun run test` and `bun run check` expect assets to have been exported once (`bun run assets`). Husky's pre-commit hook runs `bun run validate`; `bun install` installs the hook when this directory is a Git checkout. Use `bun install --frozen-lockfile` for reproducible installs from `bun.lock`. Run `bun run test` to use Vitest; `bun test` selects Bun’s built-in test runner. No commit or remote is created automatically.

## Play

| Input                        | Action                                          |
| ---------------------------- | ----------------------------------------------- |
| A / D or left / right arrows | Move                                            |
| W or up arrow                | Jump; tap again for double jump                 |
| S or down arrow (hold)       | Crouch                                          |
| J / K                        | Punch / kick (tap for each attack)              |
| L (hold)                     | Guard                                           |
| Shift                        | Dash; hold away for backdash                    |
| Left / right                 | Double-tap on ground; single tap in air to dash |
| U                            | Drill Punch (ground or air)                     |
| I                            | Axe throw (ground only)                         |
| O                            | Grab and throw (close range, ground only)       |
| H                            | Hit Up launcher; Jump on hit to chase           |
| F                            | IORI; tap again for each of two follow-ups      |
| P / Escape                   | Pause / resume                                  |
| R                            | Reset the current mode                          |

Free practice has a stationary partner and no timer. Vs. CPU adds simple deterministic approach/guard/attack behavior. Changing modes resets the round. Leaving the window pauses the match and clears held input; resume explicitly. Touch buttons support simultaneous movement and actions. Landscape is recommended on phones.

Hold crouch while attacking or guarding for low poses; attack or guard during a jump for aerial poses. Attacks finish before another can start. Landing interrupts aerial attacks, while hit/block reactions retain their remaining recovery in a ground pose. Airborne fighters land before their round-result pose. KO plays the recovered lettering sequence for 166 ticks (1.66 seconds), followed by one second with the winner visible. Rematch controls appear below the court, keeping the ending poses unobscured.

Tap punch or kick again during a standing attack to queue its next attack, up to three steps. Early taps during startup are remembered. When no follow-up is queued, the first two attacks hold their final recovery pose for an extra 150 ms to accept a late tap. Already queued attacks start at the original animation boundary; the extra recovery does not extend active hit windows. The second standing punch and jumping kick each have three strikes; the third standing kick has eight. Each strike has its own active window and hit/block effect, with inactive gaps between strikes. Their total damage stays at 10, 13, and 17 respectively, and only the final strike knocks back. Holding an attack never repeats it; getting hit clears the queued follow-up. Jump direction is chosen when jump is pressed: neutral jumps rise about 318 arena pixels, while forward/backward jumps rise about 296 and travel about 348 pixels when unobstructed. Jump travel continues after releasing direction and through aerial attacks or guard. Double jumps pause for 30 ms before launching in the newly selected direction. These velocities and acceleration use recovered actions 4–6 and 10–12, converted from the original fixed-point units to the arena scale. Each flight allows one double jump and one air dash, refreshed on landing. On the ground, two fresh taps of the same direction within 200 ms trigger a dash on keyboard or touch; opposite input, simultaneous left/right, pause, and focus loss clear the sequence. In the air, one fresh left/right press triggers a dash in that direction on keyboard or touch. Holding a direction through takeoff keeps the normal jump: release and press again to air dash. Simultaneous left/right does not select a dash direction, and the one-dash-per-flight limit still applies. These input choices, including the 200 ms ground window, belong to training mode. Dash direction follows the held movement direction, or goes toward the opponent by default. Ground dashes launch after 50/100 ms of preparation and hold their airborne pose until landing. Actions 13–14 set forward/backward velocities of +900/-500, upward velocities of -500/-900, and gravity 90 in source units. Unobstructed hops cover about 243/247 arena pixels in 180/330 ms, respectively; the backward hop is higher and slower. Air dashes retain the incoming jump or fall motion during their 30 ms preparation; if that fall reaches the floor, they land before launching. At launch they replace it with level motion at about 12 arena pixels per tick: 300 ms of level travel forward (about 360 pixels), or 200 ms backward (about 240 pixels). Their 100 ms recovery restores gravity while keeping horizontal velocity; that drift continues during the fall and aerial attacks/guard until landing or another move replaces it. Actions 16–17 supply velocity ±800 and gravity 80; the recovery motion flag `0x02` retains horizontal velocity, as does the following fall action 7. A forward air dash near the neutral-jump apex covers about 720 arena pixels through landing when unobstructed. The 960-pixel viewport scrolls over a 1920-pixel stage, so crossing the old screen edge no longer cuts off the move. Actual stage walls and body collision can shorten travel. Ground Drill Punch lunges from action ticks 11–59 (110–590 ms before contact pauses) at about 13.5 arena pixels per tick, slides at about 1.5 pixels per tick until action tick 69, then stops for its remaining recovery. Contact pauses stop this movement clock as well as the poses. Body collisions and arena walls limit its travel. It advances through six timed strikes for 3 damage each (18 total), with hit reactions and sparks on every contact and knockback on the final strike. Guard blocks all six strikes. The aerial drill holds its 220 ms startup, then dives forward at about 12 arena pixels per tick and downward at about 15; follow-up stages increase the downward speed to about 22.5. It spins until landing. Hit or block advances its contact stages; a missed spin stays armed. Damage drops from 16 to 5, 3, then 1 per subsequent contact, so its hit count depends on contact and airtime. The attacker holds position for eight contact ticks, then moves through the two transition ticks before the next strike. Landing ends the attack and plays its recovery. Its shorter 180-pixel contact range matches the diagonal blade. Axe throw launches one spinning axe per fighter; it can be blocked or jumped over. These two basic specials are meter-free. The CPU still uses its simple punch/kick/guard behavior.

Press H or the Hit Up touch button on the ground for an upward kick. It steps forward about 120 arena pixels, strikes after 150 ms of action time, and deals 15 damage. A grounded hit pauses the attacker for 330 ms and the victim for 100 ms; the victim then holds the impact pose for 250 ms before rising about 589 arena pixels and falling into knockdown/get-up. Tap Jump during startup, the contact pause, or early successful-hit recovery to chase them, then use an aerial attack. The chase prepares for 80 ms and preserves its forward momentum in the air. Blocking or missing plays the full recovery without a chase. An airborne victim instead takes a shorter hold and a stronger outward launch. The camera stays locked to the player: launching the opponent does not pan the view, while chasing them follows your own movement. The HUD stays fixed. Damage, range, the H binding, early Jump buffering, and camera following are training choices.

Press F or the IORI touch button on the ground for a three-part advancing attack. Tap again during the first stage to queue the second, then again during the second for the finisher. Early taps, including during hit-stop, are remembered; each follow-up begins after the current strike ends. Holding the button performs one stage. You can continue on hit, block, or whiff, but interruption clears the queue. Damage is 10 + 12 + 16 (38 total); guard blocks all three. The first grounded hit pushes away, the second pulls inward, and the finisher launches a grounded victim away or slams an airborne victim into a bounce and knockdown. Without follow-up input, each stage completes its recovery. The web binding, input buffering, damage, ranges, and meter-free access are training choices.

Press O within 115 arena pixels of a grounded opponent to grab them, including through guard. The grab checks after 70 ms; a miss plays its recovery, and a strike on the same tick wins over the grab. Two simultaneous grab attempts both miss. A successful grab grips the opponent for 120 ms, plays three 200 ms spinning attack cycles with the opponent held, then tosses them for 18 damage. The held pose, orbit and front/back draw order follow the same attack timeline; input cannot skip the catching attack. They fall onto the court, stay down for 600 ms, and play a 300 ms get-up before control returns. Held, thrown, down, and get-up states cannot be hit or grabbed again. Body separation stays active during knockdown and get-up. Fighter anchors stay 185 arena pixels from either stage edge so the extended air dash and wide throw/recovery poses remain visible without shifting position when the pose changes. A hit on the thrower before release frees the opponent without throw damage. Lethal throws finish on the floor without getting up; reset and timeout also release held fighters. These are authored training rules, not reconstructed original throw mechanics.

## Evidence and deliberate limits

- **Recovered behavior:** `src/game/standing.ts` ports the verified standing interpreter, including variable/collision-record assignments, branching, unsigned LCG arithmetic, timing accumulator, explicit unsupported-opcode errors, and odd-width facing placement. It executes instructions at fixed 10 ms ticks, independently of Phaser rendering. Idle action-end restarts action 1 with the continuing random seed as a new prototype choice.
- **Acceptance:** Vitest compares every event, branch, instruction, final PC, timer, and seed against 21 independently generated Python traces. The supplied seed-0 handoff timeline is also compared directly: 18 displays, nine images including 295, 223 ticks. These are comparisons against the supplied research; the original Windows game has not been run here.
- **New rules:** `match.ts` defines prototype movement, gravity, body separation, hit ranges, damage, guard, hitstun, AI, and round flow. Non-idle animation clips use deliberately selected display poses and offsets from the containers; they do not claim to execute those actions' original bytecode, physics, collisions, or transitions. CPU uses the same Ryuko art. Camera/crop is a new presentation choice.
- **Animations:** `animations.ts` loops locomotion/crouch, plays finite action and reaction sequences, and holds final airborne/ending poses. Recovered costume changes are preserved. Timing is authored where source commands wait for gameplay. The movement expansion selects actions 10, 13–17; follow-ups use 180–181 and 188–190; Drill Punch uses 207–212; Axe throw uses the source's “FIRE START” and “Fly Ball” actions 226–227 and impact 230. The third kick repeats action 190 eight times, matching the recovered loop count. Aerial drill follows the contact-dependent stages of actions 209–211 rather than playing a fixed number of spin cycles. Jump, dash, and drill movement use recovered opcode-1 velocities at source speed 10, converted to the web art scale. Air-dash entry preserves airborne velocity until the first motion command (PCs 205/223); the original action-change path at `0x410d50` clears motion only on the ground. Opcode `0x1e` controls action cancellation eligibility, not dash acceleration. Per-contact fighter pauses use recovered response timings described below. Damage, body separation, and the full gameplay VM remain training rules or unimplemented; Hit Up, IORI, and the normal KO use the recovered motion described below. Kick 3 now uses the source BEAM hit and no-time-lack guard pose sequences (83–84, 163, 165, 167). Except for Hit Up and IORI, other special launch/down responses still use the existing strong reaction poses; their full victim scripts are not executed. Axe flight uses an authored center anchor and collision rules. The source loss display is blank, so time-out loss uses the recovered seated draw pose. Guard blocks all attack heights in these MVP rules.
- **Hit Up:** action 200 supplies the upward kick, with 15 startup ticks, 10 active ticks, and 50 recovery ticks on a miss/block. PCs 2813–2815 set horizontal velocity 600 plus acceleration 350 for six ticks, then stop. A successful nonlethal hit branches to action 201; its command window for action 202 spans recovery ages 5–24. The web buffers fresh Jump presses until that window. Action 202 prepares eight ticks, then sets forward velocity 320, vertical velocity −1530, and gravity 42. Ground/crouch response 19 selects victim action 81: self/other pauses 10/33 at PC 932, a 25-tick impact hold, then velocity −160/−1700 and gravity 60 at PC 937. Air response 17 selects action 80: pauses 13/13, six impact ticks, then velocity −600/−1220 and gravity 90. Both wait for actual landing before action 146 knockdown and the existing get-up. Airborne victims remain hittable for follow-up attacks. Motion uses the same recovered fixed-point scales as jumps and dashes. Lethal contacts retain the existing normal KO path; guard retains the all-height training rule. These are static-source reconstructions, not original Windows playback verification.
- **IORI:** the source command named IORI enters action 246, with follow-ups 247–248. Display durations give startup/active/total ticks of 21/8/59, 23/8/61, and 21/5/71. Raw forward velocities are 800 at ages 13–20, 700 at 8–22, and 800 at 8–20 respectively (about 95.947, 157.413, and 155.914 unobstructed arena pixels). Source follow-up commands begin at PCs 3625/3661; the port opens transitions at action ages 29/31 and accepts them through the remaining finite recovery, with authored early buffering instead of original motion-command parsing. Ground hit responses select 75, 121, then 80: the first two pause both fighters for 15 ticks, hold nine reaction ticks, then slide away/pull inward with raw velocity −650/+650 and acceleration +10/−10. The finisher pauses 13 ticks and uses the existing outward launch. Ground guards use stop reactions 159/161 for the first two strikes (ten-tick contact pause, nine-tick pose hold, velocity −250/acceleration 8), then the existing strong block. Against an airborne victim, the first two use the existing strong air reaction approximation with 15-tick pauses. The finisher selects response 77 → action 123: 15-tick pause, nine-tick hold, then velocity −500/+2000 and gravity 100. Floor contact enters 124, holds ten ticks, bounces with velocity −400/−700 and gravity 70, then enters the 90-tick floor recovery from 147 and get-up 145. Original sound, spawned trail/smoke, color effects, mode/cancel rules, and complete victim scripts remain deferred.
- **Hit effects:** source action 345 supplies the gold hit burst; heavy hits also play the first streak branch from 348, and blocks use guard flash 370. Recovered display durations, offsets, and facing are preserved. Effects render above the fighters and expire after their last frame, including during KO; simultaneous hits keep separate effects. Selection, contact anchors, and additive blending are authored for this training mode. Full source color/effect dispatch and spawned star particles remain unimplemented.
- **Throws and recovery:** actions 196–197 supply the robot-form grab and lift/toss poses; 199 supplies the four turning poses for the catching attack, 128 and 130 supply the held and spinning reactions, 132 the airborne tumble, 146 the floor impact/down pose, and 145 the get-up sequence. Release coincides with the raised-arm pose. The long source throw and falling displays use authored timings; placement of the held fighter, launch velocity, protection, and release rules belong to the training mode. Three spin cycles and the held orbit are authored for the training mode. Original object dispatch and alternate throw variants remain deferred.
- **Stage/camera:** the supplied engine clamps stage coordinates within a 1280-pixel world (`0x40face–0x40fb96`) and horizontal camera scroll to 0–640 (`0x40b2cc–0x40b2e8`), with a 640-pixel viewport. The port uses a 1920-pixel stage and 960-pixel viewport at 1.5× scale. Camera following, the 185-pixel stage margin, and mirroring the court background to extend it are authored; the camera follows only the player on both axes, including during KO and other round endings. Horizontal scroll centers the player within the stage bounds; vertical scroll begins when the player rises above the 250-pixel dead zone and is capped at the backdrop edge. Enemy movement does not affect the camera, so distant or launched opponents can leave the viewport. HUD, KO lettering, and timer stay fixed to the viewport.
- **GUI/HUD:** the arena uses the source 640×480 aspect ratio at 1.5× scale. `hud.ts` renders the silver frame, life gradients, timer digits, portrait strips, win marks, and energy frame from `SCWU.KGT` and Ryuko's container. Screen anchors come from KGT actions 60, 71–77, 103, and 106–112. Life bars crop the original gradients. Super stock remains EMPTY; the two basic specials do not consume it. KO uses action 26's display order, offsets, and durations; its effect/control opcodes are not executed. The browser toolbar, name placement, infinity/time-out labels, and post-KO hold are authored. There is no blurred result modal. Original-game recording parity, screen effects, and round-transition dispatch remain unverified.
- **Ryuko KO:** lethal strikes use action 60's normal KO path, separately from ordinary hit reactions. After the final contact pause, its opening poses include an additional 40-tick (400 ms) hold for both fighters at PC 611; PC 607 also adds ten pause ticks to the other fighter. At action age 14, PC 617 launches backward with raw velocity −500/−1520 and gravity 90. The 25-tick launch pose then holds the falling pose until actual floor contact. Action 62 supplies the ten-tick backward slide (raw speed −200), followed by the lying pose, with no get-up. An unobstructed grounded KO travels about 420 arena pixels in flight, rises 309 pixels, and slides another 30. Both facings, airborne KOs, simultaneous KOs, and projectile endings use this sequence; lethal throws retain their separate toss/fall. Selecting this normal KO path for every lethal strike and retaining the attack's preceding contact pause are training rules. Alternate source KO branches, spawned effects, screen shake, audio, and original Windows playback parity remain unimplemented or unverified.
- **Scope:** one fighter, one stage, local single-player. Alternate/air throws, additional special variants, supers, intros, and source effect dispatch remain deferred. No full gameplay VM, original-game parity, sound mapping, gamepad, multiplayer, or public deployment. Audio is intentionally absent because original sound triggers remain unresolved.

## Recovered contact timing

A strike's active/inactive cycle uses **action ticks**. Successful contact adds **hit-stop**: the fighter's action age, airborne age, position, velocity, and acceleration stop advancing for the specified ticks. This is separate from the victim's subsequent hit/block recovery. One tick is 10 ms in this port. Whiffs add no pause. Effects and the round clock continue; fresh follow-up presses can be buffered during the pause. KO ends combat immediately and lets the final contact pause finish before the fighter's ending playback.

The uniform normal block pauses preserve this MVP's all-height guard rule; original unblockable/stance-dependent hit branches are not reconstructed. Aerial drill has a separate two-tick moving transition after its eight-tick attacker pause. Its victim resumes at different times on hit versus block, so subsequent contacts depend on their relative positions, not a fixed hit count.

Ground drill still strikes at action ages 23, 29, 35, 41, 47, 53. With every strike connecting immediately, the actual contact gaps are now **210 ms on hit** or **160 ms on block**, versus **60 ms for Kick 3**. Punch 2's first two gaps are 160 ms, and aerial kick's are 230 ms. The final strike's pause delays recovery rather than adding another strike.

Evidence: the character container tail contains 23 command entries of 82 bytes, followed by 83 four-byte response mappings at file offset `0x1576d9d`. Opcode `0x17` selects a mapping, and reaction opcode `0x1a` adds its first two bytes to the self/other fighter stop counters. The original engine handles this at `0x413637`/`0x4136ae`; `0x412390` skips animation advancement and `0x40f963` skips motion while stopped. The KGT base hit/guard stop bytes loaded at `0x43a299`/`0x43a29a` are both zero. This is static recovery from the supplied files, not original Windows playback verification. Source propagation to auxiliary objects/effects remains outside the port's fighter pause implementation.

## Files and assets

- `src/App.svelte`: accessible Svelte interface, mode selection, status, and touch controls.
- `src/game/scene.ts`: Phaser loading/rendering and keyboard lifecycle.
- `src/game/match.ts`: deterministic prototype rules and fixed clock.
- `src/game/animations.ts`: core animation timelines and frame sampling.
- `src/game/hud.ts`: source HUD rendering, health cropping, and KO playback.
- `src/game/standing.ts`: recovered idle interpreter and placement.
- `scripts/export_assets.py`: selected asset conversion and independent oracle fixtures.

The original handoff stays unchanged outside `public/`. Vite explicitly denies serving it, including through `/@fs/`. Only selected PNGs enter `public/assets/`; generated assets and fixtures are ignored by Git and regenerated locally. `dist/` contains those selected original assets and is for private development. This MVP does not publish them or establish redistribution rights.

Phaser uses its [scene lifecycle](https://docs.phaser.io/phaser/concepts/scenes); Git hooks follow [Husky's current setup](https://typicode.github.io/husky/get-started.html).
