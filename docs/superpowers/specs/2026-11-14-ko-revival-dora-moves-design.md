## 1. Re-enable the source KO Down's HP test (non-B.R. only)

### Root cause, verified against current engine paths

`Match.knockOut()` marks `f.downed = true`; a story enemy's KO can pay its configured `slot.life` and `slot.power` to an already KO'd 1P or striker. A normal KO falls and enters `koLand`. Today `land()` runs `twin(who, KO_DOWN)` as a script only for `KO_SCRIPTS` (ZAKU/PAC-HELO) and as a `KO_TIMELINES` result branch for a fighter like ZIRO; other fighters' KO Down is displayed as a clip, so its **records are never executed**.

**43 of 45** fighters have a source KO Down `life` opcode (HP ≥ 1) that resumes their own source recovery. Most follow a round-over test (global 15 = 100), but **TRAINING is an exception**: its KO Down 38 has a `life` event at **t=0 with no preceding round-over test** and targets action **113 (KNOCKDOWN, not GET_UP)**; it later reaches the ordinary knockdown recovery. DoraEmon KO Down 76 has life checks at **t=61 and t=62**, so it recovers at **61** when eligible. Other examples: Ryuko 62 → 145 at tick 60, GOLF 48 → 131, ASURA 48 → 130, TTRO 62 → 145, Z-MEGA 70 → 157 (all tick 60); ASTROMAN 61 → 143 at tick 130; RARIO 54 → 27 at tick 66. These examples are for source-driven tests/evidence, **not a hardcoded dispatch table**. ZAKU and PAC-HELO instead use their existing variable-11 KO Down BR and KO BR HP scripts, which keep precedence. The ticket's paid-KO-bonus rule still covers them, so one narrow authored path ships with implementation: after their scripted KO Down's own events run in `moveScripted`, `koDownGetUp` enters their own get-up only while no variable-11 `test` is armed, HP is positive, and the same non-B.R./open-round gate holds. No generic fallback or new state machine.

### Narrow implementation

- Use a small source-event evaluation path for KO Down: in `Match.moveKO()`'s `koLand` **clip** path, read `eventsAt(twin(f.who, KO_DOWN), f.age, f.who)` to execute the recorded round-over `test` where present and the subsequent `life` event at its native tick (including loops). Use `passes()`, `lifeMark()`, and `enterSource(f, target, offset)`, which maps native get-up _or knockdown_ targets. No settled heuristic, target table or generic fallback.
- **TRAINING's t=0 must be evaluated on entry into `koLand` in `land()`**: `land()` sets `age=0` and returns; on the next tick `move()` increments age to 1 **before** `moveKO()`, so a `moveKO()`-only rule misses its source check. Reuse the same narrow KO Down evaluation at entry (not a second recovery implementation) **once at age 0**, then let later `moveKO()` ticks run normally. If it jumps to action 113, exit `land()` immediately: do not continue `slideDown()` on the new `knockdown` action.
- For the existing `KO_TIMELINES` branch, `resultEvents()` currently enters a life target through `enterResult()`, retaining the `koLand` result action; make the KO-specific life branch enter the normal source get-up instead. **Do not** change unrelated win/draw `resultEvents` behavior or its non-KO life tests.
- Apply the authored **`!this.br`** restriction only to the KO Down life recovery. Guard both the _age-0 landing_ and later-tick paths with **`!this.winner && !this.picking && this.globals[15] !== 100`**: TRAINING has no source round-over test, so the engine must explicitly prevent post-result recovery. The other source round-over tests still run through `passes()` in their original record order. A fighter with zero HP does not branch, and leaving `koLand` makes the transition once without extra state.
- Preserve `f.downed` as true for brawl elimination and score. Preserve HPA-858's player-Dora KO RELOAD restriction and native scripted revives pending HPA-1035. For the trade-KO regression, make the lethal hit and enemy KO/`slot.life` payout happen in the **same tick's `hitTest()`** (or keep 1P above 0 until an ally earns the payout). In `run()`, `picking` latches on the first later tick seeing 1P HP=0 and cannot be undone by a subsequent heal; a bonus **one tick later** is not a valid recovery case.
- Validate the exported source shape with a table-driven test across all `CHARACTERS`, including ZAKU/PAC-HELO exceptions, native event tick targets and the B.R. `!br` boundary. Never commit generated JSON or modify extracted `.PLAYER` files.

**Why Pierce cannot be exporter-only:** action 338's frame at t=95 (PC 5793) spans the tick-100 boundary; frames in 340/341 share PCs with 339 at different ages and 342 shares PCs with unrelated 269. A PC-level protection set cannot guarantee tick 99 protected and 100 vulnerable. **`struck()` is a module-level geometry function without a Match clock; `contact()` is its current caller.** Put the guard in `contact()` to avoid changing geometry signatures; track active family membership, include hit-stop in elapsed `roundTicks`, and ensure super-cancel cannot carry immunity to a different move. No generic immunity subsystem.

For Fists, `ScriptBox.kind` is numeric and source flags use the low byte; high bit **`0x100`** identifies only the new guard box. **Rearm it from each punch event**, not once for the whole super: 327/328 emit one-tick slot-0 flurry punches every six ticks (starting t=22 through ~178) plus dash/uppercut strikes (~t=199–237); the 332 hit follow-up has active uppercut boxes (~t=94–112). Protect only those emitted active punch windows, using matching native geometry for each (flurry x=103±77); emit a zero-size/slot clear at the next tick. If the first clash calls `strip(a,b)`, that erases all of Dora's current boxes, including this guard and current punch, **intentionally**; the next source event re-arms both. The flagged clash handling must check **either holder** and escape the current pair/holder loop after stripping to avoid using a captured stale `const box`. Keep normal source-225 handler behavior and unflagged clashes unchanged.

Preserve Cannon, Gadgets, Hug, FK之意思, EN charge/KO RELOAD restrictions introduced by HPA-858, and all other fighter commands.

## 3. DoraEmon's late-arrival intro

`Match.arrive()` activates a waiting boss when its watched HP crosses the slot mark, calls `takeSeat()` and `opening(f)`. DoraEmon's `opening()` sets `f.action = 'intro'`. The pre-fight-only portion of `run()` advances Dora's existing 337-tick intro by updating age, `doraFall`, `enter`, and transition to idle. Active battle ticks instead reach `move()` and currently lack that progression.

Extract a **small `stepIntro(f)` helper** and reuse it in both code paths. Call it from `move()` **after the early hit-stop/held checks, but before `think()`, `land()` or `cancel()`** (restructure that immediate decision point carefully so the age increments once). That avoids early landing and prevents CPU commands while he is emerging. Keep existing pre-fight `cpuDriven = false`, pause behavior and first-seat timing unchanged. Do not alter `scene.ts`, waiting-seat logic, seed ordering, or other fighters' source intros.

**First-seat parity is the acceptance rule:** start counting **at actual waiting-seat arrival**, play all **337 ticks** including the sampled image frames, rise/hold/fall ending at y=0, and apply OP super Charge's **360 power / four 90-EN stocks once** (plus its Black effect) even in B.R. HPA-858 disables the voluntary/CPU charge **command**, not the intro grant. Source intro frames have **no body boxes**; Dora cannot be hit or pushed during the intro. Assert that a strike during late arrival does not connect, rather than adding immunity or hurtboxes.

One deterministic waiting-seat fixture plus the existing first-seat test verifies this shared path; do not seek three different boss orders solely to exercise one helper.

## Asset publishing and merge coordination (required)

The export changes are not just local TypeScript changes. CI and Workers builds use the R2-hosted `generated.tar.gz` / `fixtures.tar.gz`, checking the exporter's `.exporter` fingerprint. See `README.md` Deploy to Cloudflare and `scripts/upload_r2.sh`.

The implementation phase must **locally finish and verify all exporter edits together**, regenerate with `bun run assets`, then, **with the owner's explicit authorization and configured R2 credentials**, run `bun run upload:r2` **immediately before pushing** the exporter-changing commit. Since `generated.tar.gz` is a _mutable root object shared with main_, the upload creates a temporary compatibility window: old `main` builds can fail fingerprint validation until the new exporter commits merge. Coordinate the push/review/merge promptly; if authorization or credentials are unavailable, **do not claim CI/build readiness or push an exporter mismatch**. Do not invent credentials or upload while making this planning-only PR.

Immutable versioned assets live under new prefixes; uploaded generated tarballs and the exporter fingerprint are the deployment contract. No extra storage architecture or second PR.
