The first member of each lane enters immediately.

### Bounded physical seats and queue progress

Current Match instantiates every slot, uses 32-bit masks keyed by physical indices, and treats all native hostiles (including waiting ones) as the brawl win predicate. LONG can already have more than MAX_FIGHTERS native seats; MAX_FIGHTERS=10 currently gates summons, not a global native cap. Do **not** increase mask width, MAX_FIGHTERS or instantiate all 36 as Fighter objects. Only CHAOS gets recycling. Keep player and optional ally fixed, two physical seats per lane (initial first + reserved next), at most six natives. Logical queue identity is independent of physical index: per-lane cursor and last-entered identity, plus total defeated/remaining. Each lane has at most two entered bodies including a retiring body; two bosses can briefly fight each other. Once the most recently entered predecessor drops strictly below its native/scaled mark (or KOs), latch eligibility, even if the other lane is stalled. Enter the next on the first eligible simulation boundary with a free seat; if both seats are occupied, wait until an old KO is safely retired. A waiting reserve is not an entered predecessor, may not open the next gate or count as defeated. If both entered bodies KO in one tick, handle them in stable seat order; never skip, duplicate or deadlock. No inter-lane watch. Queue continues when an enemy is killed by another CPU, including a boss. No time limit.

Reuse ordinary `fighter`, `opening`, `takeSeat`, `CpuVM`, `cheatSeat` and delayed entry logic where applicable, with a CHAOS-only helper for replacement at a safe fixed-tick boundary. Preserve native KO scoring, rewards and hit-stop before recycling; retire after KO presentation/stop, not on the hit/contact loop. Authored lifecycle: once the normal KO stop has finished and down/KO presentation has reached a safe retirement boundary, a queued replacement may remove the defeated body and its residual effects (do not wait for an indefinitely held KO animation). Pin a bounded deterministic retirement point in tests, based on existing KO timing; no early replacement while its sound, contact or reward pass is still executing. A non-replaced last KO may stay until the ordinary result. Queue refill is a single atomic operation between ticks; reserve occupants not yet entered stay hidden. This is deliberately a small new CHAOS-specific lifecycle, not generic ECS or arbitrary dynamic seat renumbering.

**Reuse invariants:** keep compact fighter-index arrays aligned with seat IDs (`seats`, `slots`, `waits`, `cpus`, held/palette, inputs, previous/history/keyed/spent and any indexed simulation state). Recompute symmetric hostility for all occupied/reserved native seats on replacement/entry, by *pair identity*, not alternating physical index: 1P and ally friendly; only mates friendly; bosses hostile to every other fighter including bosses. Summons retain existing ally/enemy-of-1P relation and never count as native enemies. Audit all references to recycled index/Fighter identity: remove retiring-owned effects and trails, including queued freeing/spawn references; clear other fighters' target/caught/last-hit/throw/link references to the retired fighter/effects, releasing grabs via existing cleanup, clear old HUD enemy index, reset per-seat CPU/commands/stock/power/points/input/history/idle/palette, and ensure no old owner-index sound/attack can act as the replacement. Preserve unrelated active objects, HP, positions, tick/clock, stage, globals, cheat snapshot, queues and music. Preserve the shared CPU RNG stream (do not reset other CPUs or retain a recycled shared VM as the new owner); use a fresh VM for replacement. Select new palette against currently occupied seats including summons. Explicitly audit all index-based masks/fields in match.ts; test stale effect/target/contact references and CPU RNG. No global combat change outside CHAOS.

No-partner cheat must initialize the same two queues without the ally (existing reseatWithoutAlly compacts slots; derive lane-to-physical mapping after seating, not hardcoded indices). Replacements receive the frozen cheat HP/EN/damage rules exactly once; B.R. no-revive includes replacements, regardless of native KO scripts. Existing summons remain allowed within MAX_FIGHTERS and cannot consume reserved native slots or be retired by the queue. Preserve player loss, even if summon/ally survives. Recompute summon masks after replacement using existing summon side rules. No change to cheat menu or run-cheated state.

### Result and HUD

Expose read-only CHAOS-only `enemiesRemaining` on Match (undefined for other matches). Initialize from full logical count; decrement once per *entered logical native enemy* KO, including by enemy CPU; never for ally, summon, waiting slot, or repeat KO. Update after KO handling before the result predicate (including direct-zero fallback); a KO can count before the body is retired. In both the round-over check and `storyResult`, use logical remaining rather than current `brawlEnemies.every(downed)` when CHAOS is active. All-hostiles KO with player alive wins; player KO loses even simultaneous final KO, matching ticket's loss rule. Keep ordinary round/result/Continue and title paths, no artificial result teleport, no extra round. Continue Yes restarts all queues, HP, seats and counter on same lineup; No exits. Existing story result and ordinary B.R. rules unchanged outside CHAOS.

In `hud.ts` create one small text under the existing HUD, following ticket's in-match.png mockup (ENEMIES LEFT: N, authored styling consistent with arcade HUD). Reuse the text object; update on count, hide when not CHAOS. Arrange to avoid the existing CHEAT label, score/health/EN bars and the later achievement toast area. Keep the native no-timer HUD (zero). Use native life bars for entered ally/enemies as donated. No new UI framework, CSS overlay or asset for counter. Verify scaled layout and title/other route cleanup.

## 3. Pack residency / scene integration (necessary for a real playable route)

`TrainingScene.whenReady` currently loads every seated fighter; comments warn all 45 decode to ~6 GB. Do not put full queues in Match.fighters or whenReady's wanted set. Initial match loading = at most six native packs (1P, ally, first two from each lane) and stage; not all remaining enemies. Reuse existing `loadPlayer/residentPack/unloadPlayers`, pack loader and loading state. Keep only live/reserved native identities and summons plus **at most one upcoming unseated fighter per lane** as lookahead. Pin the bound (6+2 native packs, plus current summons; boot/select/stage assets separate; old-match transition must also release unused packs promptly once its rendered frame is no longer used). Do not evict while a sprite, afterimage, sound, queued effect or active actor still uses that fighter; retire simulation references first, hide/reset old render sprite, drop per-seat voice and idle VM, then unload only if no occupant/summon/lookahead shares Who. Preserve boot art/selection and stage audio. If lookahead isn't resident when replacement is due, hold fixed-clock advancement using a narrow request tied to the current Match/seat/candidate (no input/tick catch-up while stalled), finish the existing asset load and perform replacement only once resident. Never rebuild the match via whenReady or restart music. Reuse existing cancellation/loader failure handling: superseded route/reset/title/shutdown and late completions must not mutate the new match, request failure must report a recoverable scene error rather than seat missing art, avoid duplicate loads with summon. Do not gate simulation based on asynchronous wall-clock order; freeze the tick boundary when needed, and commit the requested swap in fixed order. No speculative preload beyond bounded lookahead. In scene.ts, detect occupant generation/identity changes per seat and recreate idle VM, palette/render/tint/sound ownership as required before consuming that fighter's first sound/render; ordinary rounds/summons keep their paths. Use focused scene tests with Phaser stub plus MCP browser network and memory/residency checks.
